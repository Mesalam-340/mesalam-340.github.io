Root Cause Analysis

The MCP tool registry trusts the role claim inside the JWT payload without verifying the signature when alg is set to none. Since the server itself advertises none as a supported algorithm, an attacker only needs to change the algorithm header and drop the signature to be treated as any role they choose, including admin.

This means I now have full admin privileges on the MCP server and can register any tool with any Python code I want, which effectively gives me remote code execution on this server. Now I want to try running the tool to see whether it actually works or not.

The tool actually works — the response shows a text output of 1, which is the real result of executing print(1) in Python on the server, meaning the code was genuinely executed and not just registered successfully. isError is also false, confirming the execution completed without errors.
