Pre-Account Takeover via Weak OTP & Missing Rate Limiting

Omar Mesalam • Bug Bounty • Broken Authentication

While testing the application, I found the email verification feature during the sign-up flow. This report explains how a combination of a weak 5-digit OTP and the absence of rate limiting on the verification endpoint allowed a pre-account takeover, where an attacker can bind and verify an email address before its real owner ever creates an account

AUTH Email Verification — OTP Brute Force

  • While testing the application for vulnerabilities I came across the email change feature
  • I opened Burp Suite to intercept the requests and analyze how the verification flow works between the client and the server
  • I found that when I entered my email address, the application sent a verification code I also noticed that the verification code expires after 10 minutes
  • So, I decided to try entering some random codes and see how the server responds
  • Then, I decided to check whether the endpoint had any rate limiting in place
  • I sent 20 consecutive requests, and all of them were processed normally without triggering any rate-limit response
  • At this point, I decided to inspect the verification code I received and verify its format. I found that it consisted of exactly five digits and contained numbers only, which makes it relatively easy to brute-force within the 10-minute expiration window
  • Unfortunately, after several attempts I discovered that the code had to be within the range of 00000 to 03300 so that I could guess it before the 10minute timer expired
  • I started guessing sequentially from 00000, and 03300 was the highest value I was able to reach within the 10 minute window
  • Although it may take a while to demonstrate the impact, it should eventually work
  • Finally The Account Has Been Successfully Activated ✅
  • Since the verification code consists of only 5 digits and the endpoint has no rate limiting, an attacker could bruteforce the code within its time window and activate the account just by knowing the victim's email, without needing their password or any interaction from them
