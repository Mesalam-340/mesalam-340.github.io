PORT 111 rpcbind / NFS

Now we have service rpc with version 2 (RPC #100000). Excellent, this result is very important because it revealed the RPC attack surface on the device:

RPC Services ├── NFS → 2049 ├── mountd → 56732 / 59240 ├── nlockmgr → 38662 / 46870 └── status → 40651 / 38082
┌──(root㉿omar)-[/home/mesalam] └─# showmount -e 192.168.68.129 Export list for 192.168.68.129: / *

This NFS misconfiguration is very dangerous because sharing / in full greatly expands access, and may allow the client to read system files, and possibly write as well depending on the export options.

Meanings:

  • Read: You can read.
  • Lookup: You can view names.
  • Modify: Allows modification.
  • Extend: Allows adding/extending files.
  • Delete: Allows deletion.
  • NoExecute: Files are not executed directly from the NFS mount with the execute permission.

Therefore, the export is not just read-only; Nmap sees modification, write, and delete permissions on the exported file. This makes misconfiguration extremely dangerous.

The result we demonstrated:
- An external attacker without credentials can mount the / file system via NFS ✅
- They can view the target filesystem from their machine ✅
- We have evidence of broad privileges (Read, Modify, Delete...) from NFS enumeration ✅
