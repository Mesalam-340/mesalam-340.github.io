Now what we have from this enumeration:

  • SSH-2.0 — The server supports SSH protocol version 2
  • OpenSSH — The SSH server software is OpenSSH
  • 4.7p1 — The OpenSSH version
  • Debian-8ubuntu1 — Package/build information from the Linux distribution

Now let's try some enumeration with the ssh-audit tool:

Key Findings: - OpenSSH 4.7p1 (Very old OpenSSH version. Worth checking for known vulnerabilities) - Weak Key Exchange (KEX): diffie-hellman-group1-sha1 (1024-bit DH modulus. Vulnerable to Logjam and uses weak SHA-1) - Weak Host Key Algorithms: ssh-dss (1024-bit, deprecated), ssh-rsa (relies on SHA-1, deprecated in modern OpenSSH) - Weak Encryption / Ciphers: 3des-cbc, blowfish-cbc, cast128-cbc, arcfour / RC4 (broken/legacy CBC-based ciphers) - Weak MAC Algorithms: hmac-md5, hmac-sha1, hmac-sha1-96, hmac-md5-96 Potential Connection Throttling Issue: - SSH accepted approximately 397 connections/sec during audit. - Flagged potential exposure to DHEat DoS (CVE-2002-20001).

We now know that there are weaknesses in the encryption and keys, and this service is outdated and vulnerable to many weaknesses including DoS, but this is not our ultimate goal.

Now we find a User Enumeration vulnerability.

This seemingly minor vulnerability might be the key to gaining initial access. Now that I know there's a user named Root, my mind goes to BruteForce.

It seems there's no default password that works with root directly, so we'll try credentials harvesting across users.

PORT 111 rpcbind / NFS

Now we have RPC service running version 2 (RPC #100000).

Excellent, this result is very important because it revealed the RPC attack surface on the target device:

RPC Services ├── NFS → 2049 ├── mountd → 56732 / 59240 ├── nlockmgr → 38662 / 46870 └── status → 40651 / 38082
┌──(root㉿omar)-[/home/mesalam] └─# showmount -e 192.168.68.129 Export list for 192.168.68.129: / *

This NFS misconfiguration is very dangerous because sharing / completely expands access, allowing reading and writing system files based on export permissions.

Privilege Definitions:

  • Read: You can read files.
  • Lookup: You can view file names.
  • Modify: Allows modification.
  • Extend: Allows adding/extending files.
  • Delete: Allows deletion.
  • NoExecute: Files are not executed directly from the NFS mount.

Therefore, the export is not just read-only; Nmap sees modification, write, and delete permissions on the exported file system.

  • An external attacker without credentials can mount the / filesystem via NFS ✅
  • They can view the entire target filesystem from their machine ✅
  • Broad privileges (Read, Modify, Delete) confirmed via NFS enumeration ✅
